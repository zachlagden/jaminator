## Phase Goal

**As a** Jam Coding technician, **I want to** install Jaminator by double-clicking the MSI on any classroom laptop, **so that** the install completes without the SFXCA CLR-load failure that rolls back v0.7.4's install path.

<objective>
Physically delete the `installer/UpdateCheck/` project directory (`UpdateCheckCA.cs`, `UpdateCheck.csproj`, plus any `bin/`, `obj/` build artifacts) and then verify at the MSI artifact level that the rebuilt installer carries no UpdateCheck custom-action surface. This is the final INSTALL-03 verification gate per D-09 (build + MSI inspection).

Purpose: Two phases of work — first, a `rm -r installer/UpdateCheck/` directory removal (D-01, D-11 commit 3); second, a Windows-side validation pass that runs `dotnet build Jaminator.sln`, then `installer/build.ps1`, then `lessmsi l -t <Table>` against the rebuilt MSI to prove the three target identifiers (`UpdateCheckCA`, `CheckForNewerVersion`, `Wix4DTFCustomAction`) appear in ZERO rows of the Binary, CustomAction, and InstallUISequence tables. The build-script-exit-code gate alone is necessary but not sufficient — RESEARCH.md cites that `wix build` will happily emit an MSI without the CA but with stale references if any survive, and only direct table inspection proves the strip.

Output: An empty repo state where `installer/UpdateCheck/` does not exist, plus a `build/Jaminator.msi` artifact (transient — not committed; used only for verification) that demonstrates a clean MSI build. The verification commands are run on Windows; this plan has `autonomous: false` because lessmsi installation + powershell execution requires the user's Windows dev box.
</objective>

D-09 verification commands (PowerShell on Windows):

```powershell
# A) Build prerequisites probe
dotnet --version          # expect 8.0+
wix --version             # expect 4.x or 5.x
Get-Command lessmsi -ErrorAction SilentlyContinue  # null → install via winget/choco

# B) Clean and rebuild
Push-Location $repoRoot
dotnet clean Jaminator.sln           # flushes stale obj/bin from previous UpdateCheck builds
dotnet build Jaminator.sln -c Release | Out-Host
if ($LASTEXITCODE -ne 0) { throw "dotnet build failed" }
.\installer\build.ps1                # produces build\Jaminator.msi
if ($LASTEXITCODE -ne 0) { throw "installer/build.ps1 failed" }

# C) Artifact-level inspection (the D-09 gate)
$msi = "$repoRoot\build\Jaminator.msi"
Test-Path $msi              # must be True

# All three pipelines below MUST produce zero output. Any row → strip incomplete.
lessmsi l -t Binary           $msi | Select-String UpdateCheckCA
lessmsi l -t CustomAction     $msi | Select-String "CheckForNewerVersion|Wix4DTFCustomAction"
lessmsi l -t InstallUISequence $msi | Select-String CheckForNewerVersion

# D) Final repo state probe
Test-Path installer\UpdateCheck       # must be False
Test-Path installer\UpdateCheck\bin   # must be False (no stale build output)
Pop-Location
```

Fallback if lessmsi unavailable (RESEARCH.md Standard Stack table):
```powershell
& wix msi decompile build\Jaminator.msi -o build\decompiled.wxs
Get-Content build\decompiled.wxs | Select-String "UpdateCheckCA|CheckForNewerVersion|Wix4DTFCustomAction"
# Must return zero matches
Remove-Item build\decompiled.wxs
```

The fallback has known caveats around binary extraction and modularization GUIDs (RESEARCH.md cites wixtoolset/issues/7574), but for the three identifiers above the `.wxs`-grep approach is exact.
