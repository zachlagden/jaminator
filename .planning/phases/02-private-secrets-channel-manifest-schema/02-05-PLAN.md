<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| EXE launch path → `BuildSecrets.WifiPat` const | The fail-fast guard is the gate. An EXE with placeholder PAT never reaches the network, the UI, or any per-mode handler. |
| `MainForm.OnLoad` → log file | The PSK is in memory inside `_manifest.Wifi.Profiles[i].Psk` but is NEVER projected into the log line. The format string interpolates `_manifest.Wifi.Profiles.Count` and `.Select(p => p.Ssid)` only — there is no `.Select(p => p.Psk)` anywhere in the codebase as of this plan. |
| Log file → any user with `%ProgramData%` read access | `%ProgramData%\Jaminator\logs\` is world-readable by default on Windows. The literal `***` mask is the only PSK representation that reaches the file. |
| `%TEMP%\Jaminator-fail-fast-*.log` → any user with `%TEMP%` read access | The fail-fast log contains the error message naming `installer/build.ps1` and `installer/secrets/README.md` — but NEVER the PAT value itself. The guard intentionally doesn't echo `BuildSecrets.WifiPat`. |

| T-02 (placeholder-bypass) | Information Disclosure / Logic Error | A developer running `dotnet build` directly bypasses `installer/build.ps1`, producing an EXE that reaches GitHub with the literal placeholder `@@PAT@@` (RESEARCH.md Pitfall 2) | mitigate | Program.Main fail-fast guard checks for empty string AND the literal `@@PAT@@` marker at the earliest possible point — before `ParseMode`, before any I/O, before any UI initialisation.
