<objective>
Stand up the build-side plumbing that injects the Wi-Fi PAT and private-secrets URL into the EXE at build time without leaking them to source control. Three pieces:

1. **Gitignore + secrets directory** — `installer/secrets/` exists in the repo (so the operator has a known drop point) but its contents are gitignored except for `.keep` and `README.md`. `src/Jaminator/Generated/` is gitignored in full (the generated `BuildSecrets.g.cs` is never committed).
2. **PAT/URL resolution in `installer/build.ps1`** — file-first, env-var fallback, fail-fast with operator-actionable error message (D-04).
3. **Generated `BuildSecrets.g.cs`** — `installer/build.ps1` writes the C# source file to `src/Jaminator/Generated/BuildSecrets.g.cs` before invoking `dotnet build`. The Microsoft.NET.Sdk auto-glob picks it up (RESEARCH.md Pattern 2; verified — no csproj edit needed).
4. **Operator runbook** — `installer/secrets/README.md` documents what to drop where, PAT scope, rotation cadence, env-var fallback, and the threat-model honesty pointer.

Purpose: Plans 02-03 (fetcher) and 02-05 (debug log + fail-fast guard) compile against `Jaminator.BuildSecrets.WifiPat` and `Jaminator.BuildSecrets.SecretsUrl`. Without this plan's generation step, those references are unresolved symbols.

Output: Four files modified/created. After this plan plus plan 02-01, the solution builds end-to-end on a Windows box with the operator pre-conditions satisfied, but no runtime code yet exercises `BuildSecrets` (the fetcher and the log emit land in plans 02-03 / 02-05).
</objective>
